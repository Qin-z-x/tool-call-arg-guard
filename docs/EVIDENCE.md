## Scope and honesty statement

`toolarg-guard` is a defensive argument validator. It does not disclose a new vulnerability, does not claim a new CVE and does not make a dangerous tool call safe: command injection (CWE-78), path traversal (CWE-22) and SSRF (CWE-918) are well-known public classes. The tool reduces the chance that a model-generated argument reaches a shell, file API or HTTP client in a damaging form; it is not a sandbox and it is not a model-level guard.

## Limitations

- Rules are heuristic: crafted quoting, encodings and argument shapes can evade pattern checks; do
  not treat a clean result as proof the call is safe.
- Shell rules run only on command-like tools/argument names (documented in README); path and URL
  rules run on every string. This context split intentionally trades some recall for precision.
- JSON-Schema support is a subset (type/properties/required/additionalProperties/items/enum/
  length/pattern/min/max/anyOf/oneOf); unsupported keywords are ignored, not enforced.
- The real mitigation is least privilege: parameterised tool implementations, no shell string
  interpolation, filesystem root confinement and an egress allowlist.
- The tool validates arguments, not tool output or the model's intent.
